# 拆分策略与手法

## 何时拆分

- 用户通过 `<split_plan>` 明确要求拆分。
- 变更涉及多个独立逻辑模块，单次提交标题难以概括。
- 变更同时包含新功能和 bug 修复，应各自独立提交。

无 `<split_plan>` 且变更逻辑单一时，合并为 1 次提交，不读此文件。

## 拆分手法

1. 根据 `<split_plan>` 或变更分析，确定每次提交的意图和对应文件。
2. 若拆分边界不明确（如某文件同时属于两个逻辑），用 `question`（单选）让用户确认该文件归属哪次提交，选项为各候选提交。
3. 按逻辑顺序逐次执行：
   - `git add <该次提交的文件>`（只加相关文件，不用 `-A`）
   - `git commit`（按 `commit-message.md` 格式撰写）
4. 每次提交独立完整——一次提交 = 一个可独立回滚的逻辑单元。
