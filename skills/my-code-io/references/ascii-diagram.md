# ASCII 图绘制规范

仅在初级分流命中"简单内容"时读取本文件。绘制全程保持二次分流警觉：命中征兆立即改道。

## 适用场景（白名单）

ASCII 图只画以下类型，白名单之外一律交 `Skill` 工具调用 `my-mermaid`：

- **tree 类**（强项）：目录树、层级结构。很长的 tree 正是 ASCII 的优势——mermaid
  也能画 tree，但过长反而难看，这正是 tree 不交给 my-mermaid 的原因。
- **极简线性流程**：基本无分支（A → B → C）。
- **对照/枚举小结构**：Markdown 表格不适合表达的简单纵向枚举。

## 宽度与对齐规则

- 每个汉字/全角字符（含中文标点、全角符号）显示宽度**固定按 2** 计算；ASCII 字符按 1。
- box-drawing 框线字符（`├`、`└`、`│`、`─` 等）按 1 计算，但其实际宽度随环境有歧义
  （East Asian Ambiguous，部分终端渲染为 2）——含框线字符的行只用于左对齐结构
  （如树形前缀），**不得参与右侧对齐计算**。
- 需要对齐的行，逐行计算显示宽度：`ASCII 字符数 × 1 + 全角字符数 × 2`，按显示宽度
  补空格，**不得按字符数对齐**。
- 优先选**不依赖右侧对齐**的形态：
  - 树形用 `├── └── │` 前缀，左对齐天然成立；
  - 避免右侧封闭边框——右边框要求每行精确等宽，是汉字宽度错乱的高发区。

## 宽度与长度的不对称约束

ASCII 图**只有宽度限制（显示宽度 ≤ ~80 列），没有长度限制**。行数多不是劣势，
是优势（尤其 tree）。

宽度不足时按序处理（命中即停）：

1. **转置**：调换布局方向，把宽度压力转为长度（如横向流程改纵向排列）。
2. 转置后仍超宽、或结构无法转置 → 改用 `Skill` 工具调用 `my-mermaid`，
   或拆分为多个 ASCII 图。

## 绘制约束

- 树形统一用 box-drawing 前缀字符（`├──`、`└──`、`│`），不用 `|--`、`+--` 等
  ASCII 近似写法（含经典 tree 命令输出中反引号开头的连字符变体）。
- 线性流程用 `→`（横向）或 `│`/`↓`（纵向）简单连接。
- **不画封闭方框 + 连线组合的"框图"**——产生画框冲动本身就是二次分流信号。

## 二次分流（绘制中与完成后自检）

出现以下任一征兆，立即放弃当前 ASCII 图，改用 `Skill` 工具调用 `my-mermaid`
（传入该图要表达的内容描述）：

- 结果不规律，需要反复修补对齐；
- 分支超过 2 个，或出现交叉连线；
- 画出了 ASCII 框图（方框 + 连线的组合结构）；
- 宽度超限且转置、拆分都无解；
- 读者需要"看懂结构关系"而非"看清列表层级"。
