# Mindmap

## 选型

层次化知识结构、概念分解。项目目录概览、技术体系全景、功能拆解。

## 语法

```
mindmap
  root((项目架构))
    前端
      React
        组件库
        状态管理
        React Router
      TypeScript
        类型定义
        工具类型
    后端
      API
        REST
        GraphQL
      数据库
        PostgreSQL
        Redis
    部署
      Docker
      CI/CD
        GitHub Actions
        自动测试
```

- 缩进控制层级，用 2 空格
- 根节点 `((...))` 圆形，一级节点自动方形，更深节点自动圆角
- 节点文本**无引号机制**：避免 `()[]{}`（形状定界符）及 `@#&<>` 等特殊符号，必要时用全角括号（）替代；文本以中文/字母/数字为宜
- 同级自动分配不同颜色，无需 classDef
- 叶子节点尽量简短（4-8 字）

## 配色

mindmap 自动按层级着色，不支持手动 classDef。每层自动区分色相，深→浅随层级递进。

## 大小限制

超 4 层或 25 节点时提示精简——深层嵌套可读性下降，考虑将深层子树拆为独立 mindmap。

## 最佳实践

- 根节点概括核心主题（如"项目架构"、"React 生态"）
- 一级分支为顶层分类（≤ 6 个）
- 叶节点简短，不写完整句子
- 适合"概览全景"，不适合精确流程或数据关系
